Problem

Claude Code 很强大，
但专家配置仍然困难。

一个普通用户想让 Claude Code 成为交易大师，不能只靠一句 prompt。他需要配置 Skills、Subagents、MCP、Hooks、规则、记忆、测试和权限——这是整套 agent engineering。

01 · 用户侧断点

用户不会写 Skill

普通用户不会手写 Skill、配置 MCP server、编写下单前 Hook，也不知道专业工作流应该长什么样。

02 · 创作者侧断点

专家无法变现能力

专家可以卖课、分享 prompt，但很难把自己的专业能力变成用户 Claude Code 项目里可运行的结构化能力包。

03 · 支付侧断点

Agent 需要原生支付

AI Agent 需要按次购买能力包、数据和服务，传统账号订阅和手动支付流程完全不适合 agent-native 场景。

Solution

DNAcloud 把专家能力打包成
可安装的 DNA。

DNA 包不是 prompt，不只是 Markdown。它是一个会改变 Claude Code 项目能力结构的可安装单元。

一个 DNA 包包含什么？

安装后，Claude Code 项目获得全新的专家工作流、子代理、快捷命令和 MCP 工具集成：

⚡

Skills

自然语言触发的专家工作流，例如 trading-master、contract-review

🤖

Subagents

专注子任务的 AI 子代理，例如 market-analyst、risk-manager

⌘

Slash Commands

快捷命令，例如 /trade-plan、/risk-check、/order-preview

🔌

MCP 配置模板

外部服务工具集成，仅写环境变量引用，不含真实 key

更多组件

🪝

Hooks

工具调用前后的约束逻辑，例如下单前风险检查 PreToolUse

📋

Machine Rules

机器可读规则：风险上限、权限策略、安装约束

🧪

Conformance Tests

安装后验证用例，prove 能力包已 active

配置 OKX x402 支付凭证 购买 DNA 必需

购买 DNA 包通过 OKX x402 协议完成链上支付，需要 OKX OnchainOS 开发者凭证。没有凭证时，DNAcloud Skill 会自动引导你完成以下配置：

⚠️ 这不是 OKX 交易所的普通 API Key，而是 OKX OnchainOS 开发者门户专用凭证，请注意区别。
获取 OKX OnchainOS 凭证（4 步）
1 打开 OKX OnchainOS 开发者门户（web3.okx.com/onchainos/dev-portal）
2 连接 EVM 钱包（MetaMask 等），签名验证消息证明钱包地址所有权，无需充值
3 在开发者门户创建 API Key，保存三个凭证：API Key、Secret Key、Passphrase
4 写入项目 .env 文件
OKX_API_KEY=your_api_key
OKX_SECRET_KEY=your_secret_key
OKX_PASSPHRASE=your_passphrase
⚠️ 不要把 .env 提交到 Git。如未配置直接说"我要安装 DNA"，DNAcloud Skill 会主动引导你完成这步。参考：OKX x402 支付文档
4

FAQ

常见问题

黑客松评委和早期用户最关心的问题。

DNAcloud 和 prompt 市场有什么区别？ ⌄
Prompt 只改变对话风格，DNA 包会改变 Claude Code 项目的能力结构。安装后，用户获得新的 Skill（触发专家工作流）、Subagent（执行子任务）、Slash Command、MCP 配置、Hook（约束危险操作）、机器规则和验证测试。这些都是真实安装到项目文件系统的组件，不是文本对话。
为什么用 OKX x402 而不是传统支付？ ⌄
DNA 包是 AI Agent 可按需获取的数字资源。x402 让客户端请求资源时收到 HTTP 402 payment requirement，签名付款后获得资源，非常适合 agent-native commerce——不需要注册账号、管理订阅或接入支付网关。这是专为 AI Agent 和 CLI 设计的支付方式。
为什么从 Trading Master DNA 开始？ ⌄
交易场景足够复杂，可以展示完整能力链路：市场数据 MCP、账户读取、下单、风险规则、策略流程、资金管理、复盘、Hook 拦截。我们不承诺盈利，目标是证明复杂专家能力可以被购买、安装和验证——即能力安装闭环。
Trading Master DNA 能保证盈利吗？ ⌄
不承诺盈利。Trading Master DNA 提供的是交易能力结构——交易分析、资金管理、策略工作流、风险检查、订单预览和复盘能力。真实交易风险由用户控制。未配置真实 MCP 凭证时，系统会提示配置，不会生成假数据。
创作者如何赚钱？收款流程是什么？ ⌄
创作者上传 DNA 包时填写收款地址（EVM 钱包）。买家购买后，支付先进入平台公共账户，平台账本记录创作者应收（净收益 80%），异步结算 worker 定期将资金打到绑定的收款地址。创作者无需手动申请提现。
平台如何保证 DNA 包安全？ ⌄
第一期采用自动化多层审核：manifest 完整性校验、ZIP 路径穿越攻击防护、私钥/助记词/JWT 扫描、危险命令检测（curl|bash 等）、文件类型白名单。安装时提供安装预览，安装后运行 conformance tests 验证，并保留 rollback 快照。
DNAcloud 未来会支持 Cursor、Codex 等其他 AI 平台吗？ ⌄
是的。DNAcloud 的定位是 Universal AI Agent DNA Registry。Claude Code 是当前已支持的平台，Cursor、OpenAI Codex、Windsurf 等计划在 Phase 3 陆续支持。DNA 包的 MCP 配置和 manifest 格式从设计上就考虑了跨平台兼容性。
DNAcloud 和 ClaudeHub、Skill 市场有什么区别？ ⌄
ClaudeHub 等 Skill 市场提供的是人工查找、手动复制粘贴的 Skill 文件，用户需要自己了解如何配置 MCP、Hook 和规则。DNAcloud 的核心差异在于三点：

① 可安装，不是可阅读——DNA 包通过 CLI 一键写入项目文件系统，Skills / Agents / MCP / Hooks 全部自动到位，无需手动操作；

② 链上原生支付——基于 OKX x402，AI Agent 可以自主完成按次付费购买能力包，不依赖传统支付账号；

③ 跨平台标准——DNA 包格式设计为平台无关，同一个包可以安装到 Claude Code、Cursor、Codex 等不同 AI Coding Agent，而不是绑定单一平台。
